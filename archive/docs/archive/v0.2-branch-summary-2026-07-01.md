# v0.2 ブランチ総括 2026-07-01

## 目的

`work/v0.2-dependency-upgrade` は、v0.1 系の延長で小さく直すだけのブランチではなく、Babylon.js / babylon-mmd 更新後の MMD_modoki を次の実験基盤へ進めるための検証ブランチとして進めた。

主な狙いは次の 4 つ。

- Babylon.js 9 / babylon-mmd 1.2 系へ上げても MMD 編集・再生が壊れないか確認する。
- 物理、タイムライン、キー編集、UI の土台を v0.2 向けに整理する。
- FrameGraph を post effect backend の標準候補として試し、順序変更可能な効果 stack を作る。
- 実験で得た制約や危険箇所を docs に残し、main 統合後に迷わないようにする。

## 大きく進んだこと

### 依存更新

- Babylon.js core / gui / loaders を 9.2.0 系へ更新。
- babylon-mmd を 1.2 系へ更新。
- Vite / Vitest 更新候補を検証し、Vite 8 系は後続候補として切り分けた。
- `smoke:launch` で WebGPU 起動、renderer runtime 初期化、MPR runtime 初期化を確認した。

### 描画 / FrameGraph / PostFX

- FrameGraph backend を、MMD scene render 全体の置き換えではなく post effect backend として実装した。
- FrameGraph post stack を追加し、順序変更、個別 ON/OFF、project save/load に対応した。
- ON/OFF と効果パラメーターを分離し、OFF にしても色や強度などを保持する方針にした。
- `Offset Shadow` を追加した。
- `Offset Rim` を追加した。internal id は `offsetHighlight`。
- `Offset Rim -> Bloom` の順に並べると、リムに Bloom がかかることを実機確認した。
- `Luminous` を FrameGraph stack の効果として整理し、Bloom とは役割を分けた。
- WebGPU FrameGraph の texture 依存は build 後に固定されるため、stack order / enabled 変更は live reconnect ではなく backend rebuild に寄せた。
- FrameGraph / PostFX の危険メモを追加した。

残り:

- rapid reorder / rapid toggle の debounce。
- Offset Shadow / Offset Rim の model mask または receiver mask。
- Offset Rim の thickness 増加時の線ぶれ軽減。
- 外部 LUT と PNG / WebM 出力への反映確認。
- SSR 用材質プリセット方針。
- SSAO2 / SSR の WebGPU 安定性と負荷確認。

## main 統合前に意識すること

- FrameGraph / PostFX は動いているが、まだ実験寄り。危険メモを残した前提で統合する。
- Classic / FrameGraph の二重適用を避ける。
- stack order / enabled 変更は backend rebuild に寄せる。
- `frameGraphPostStack` と各効果パラメーターを分けて扱う。
- `offsetHighlight` は互換上 internal id として残し、UI では `Offset Rim` と表示する。
- MPR packaged build は未完なので、package 版の物理 fallback 挙動を明示しておく。
- PNG / WebM 出力、外部 LUT、SSR / SSAO2 の実機品質は統合後も確認対象。

## 確認コマンド

```powershell
npm.cmd run lint
npm.cmd run test:unit
npm.cmd run smoke:launch
npm.cmd run log:errors
```

描画 / runtime 初期化に触った場合は `smoke:launch` を追加確認として扱う。FrameGraph / PostFX の表示品質、PMX / VMD 実読み込み、PNG / WebM 出力は smoke だけでは確認できないため、手動確認を別途行う。

## 統合後の最初の作業候補

1. FrameGraph / PostFX の手動確認チェックリストを小さく作る。
2. Offset Shadow / Offset Rim の model mask 方針を決める。
3. FrameGraph stack rebuild debounce を入れるか判断する。
4. PNG / WebM 出力で FrameGraph post stack が反映されるか確認する。
5. MPR packaged build fallback のユーザー表示を整理する。
