# v0.2 main 統合計画 2026-07-01

## 目的

`work/v0.2-dependency-upgrade` を、v0.2 開発ブランチとして `main` へ統合する。

このブランチは単一機能の小さな差分ではなく、依存更新、物理、キー編集、UI 整理、FrameGraph / PostFX、材質・テクスチャ互換、docs 整備を含む大きな開発ブランチとして扱う。

## 統合方針

- 細かい機能ごとに切り出して cherry-pick するのではなく、v0.2 開発ブランチとして Pull Request でまとめて統合する。
- PR は「差分を全部理解する場」ではなく、「不要ファイル混入、危険制約、最終確認項目を見る場」として使う。
- main 統合前に docs の総括、危険メモ、チェックリストを整えてから commit / push する。
- merge 方式は、作業履歴を残すため通常 merge commit を第一候補にする。履歴を圧縮したい場合だけ squash merge を検討する。
- release tag と混ざらないよう、main 統合前の作業ブランチ側スナップショットには `v0.2.0_branch` tag を切る。正式 release tag の `v0.2.0` は main 統合後、release 確認が済んでから別途切る。

## tag 方針

- `v0.2.0_branch`
  - `work/v0.2-dependency-upgrade` の統合前スナップショット。
  - 大きなブランチを main へ統合する前の退避点として使う。
  - release tag ではない。
- `v0.2.0`
  - main 統合後、release 前確認が済んだ時点で切る正式 release tag。
  - 配布物や GitHub Release と紐づける場合はこちらを使う。

想定コマンド:

```powershell
git tag -a v0.2.0_branch -m "Snapshot v0.2.0 development branch before main merge"
git push origin v0.2.0_branch
```

## 既知制約として残すもの

- FrameGraph / PostFX はまだ実験寄り。
- Classic / FrameGraph の二重適用を避ける必要がある。
- stack order / enabled / resource 変更は backend rebuild が必要。
- Offset Shadow / Offset Rim は model mask / receiver mask が未整理。
- Offset Shadow は遠方 / 背景、Offset Rim は手前床 / 背景へ出るケースが残る。
- Offset Rim は thickness 増加時に線ぶれが出るケースがある。
- package 版で MPR worker helper / wasm asset 統合は未完了で、SPR fallback 前提。
- PNG / WebM 出力、外部 LUT、SSR / SSAO2 は release 前に最終確認する。

## 統合後の確認

1. `main` を最新化する。
2. merge 後の `main` で `npm.cmd run smoke:launch` を実行する。
3. 代表プロジェクトを読み込む。
4. Offset Rim -> Bloom を再確認する。
5. project save/load を確認する。
6. 問題なければ v0.2 release 準備へ進む。
