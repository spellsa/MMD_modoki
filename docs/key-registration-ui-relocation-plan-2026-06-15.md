# キー登録 UI 再配置案 2026-06-15

## 目的

キー登録まわりの UI を、現行の下パネル中心からタイムライン下へ寄せる案を整理する。

現行では暫定的に下パネルへ `ボーン操作`、`ボーン数値`、`モーフ` を並べているが、横幅が不足しやすい。
特にモーフ欄はスライダーと数値入力を横に使うため、下パネル上で広く取りたい。

そのため、v0.2 の次段階では次の方向を検討する。

- ボーン操作 / キー登録操作はタイムライン下へ移す
- 下パネルはモーフ、補間、対象情報、カメラ/照明などの現在値編集を優先する
- キー操作は「タイムラインの一部」として扱い、時間軸に近づける

## 背景

既存メモ [キー登録 UI 配置メモ](./key-registration-ui-note-2026-04-18.md) では、キー登録の主置き場を下パネル寄りに考えていた。

ただし、その後の UI 整理で次の問題が見えてきた。

- 下パネルにボーン操作を置くと、モーフ欄が狭くなる
- ボーン登録、物理 ON/OFF、コピー/削除などはタイムラインと距離が近い方が分かりやすい
- MMD 本家も、タイムライン下に選択ボーン、範囲、コピー、削除、物理 ON/OFF 登録などを集めている
- 下パネルはモーフや照明のように、複数スライダーを並べる編集面として使いたい

したがって、旧方針を完全に破棄するのではなく、次のように役割を分け直す。

```text
タイムライン下
  キー登録 / 選択キー操作 / ボーン操作 / 物理 ON-OFF 登録

下パネル
  現在値の詳細編集 / モーフ / 補間 / 情報 / カメラ / 照明 / アクセサリ
```

## 配置方針

### タイムライン下へ移したいもの

タイムライン下は「現在フレームと選択キーに対する操作」を置く場所にする。

候補:

- 登録
- 削除
- コピー
- ペースト
- 反転ペースト
- 初期化
- 未登録選択
- 全て選択
- BOX 選択
- 選択対象の切替
- 物理 ON / OFF
- 物理 ON/OFF キー登録
- 選択ボーン名 / 対象 track 表示

この領域は MMD 本家の `ボーン操作` と `フレーム操作` の中間のように扱う。

### 下パネルに残したいもの

下パネルは、スライダーや数値入力を使う現在値編集に寄せる。

候補:

- モーフ欄
- 補間欄
- モデル情報
- カメラ位置 / 角度 / 距離 / FoV
- 照明方向 / 光色 / 影色
- アクセサリ transform
- 選択キーの詳細値

ボーン transform の数値表示は、将来的にはタイムライン下へ移すか、ビューポート上の補助表示へ分けたい。
ただし、カメラ transform は下パネルに残す方が自然な可能性がある。

## UI 構成案

### 左タイムライン下: キー操作ドック

左タイムラインの直下、またはタイムラインと下パネルの間に薄い dock を置く。

```text
┌──────────────────────────────┐
│ 登録  削除  コピー  ペースト 反転P │
│ 対象: 選択ボーン ▾  範囲: 現フレーム │
│ 物理: ○ON ○OFF  [登録]             │
└──────────────────────────────┘
```

狭い場合は 2 段にする。

```text
[登録] [削除] [コピー] [ペースト] [反転P]
対象 [選択ボーン ▾]  物理 [ON] [OFF] [登録]
```

### ビューポート下バーとの関係

ビューポート下バーは再生シークとフレーム移動に使っているため、キー登録ボタンを増やしすぎない。

置くとしても補助的な導線に留める。

- 現在フレーム
- 再生 / 停止
- シークバー
- 画像保存 / fullscreen
- 必要なら小さい auto key toggle

`登録` の主導線はタイムライン下へ寄せる。

### 下パネル: モーフ優先レイアウト

モデルモードでは下パネルの幅配分を次のようにしたい。

```text
情報 | 補間 | モーフ（広め） | モーフ（続き） / その他
```

または:

```text
情報 | 補間 | モーフ 2列 | アクセサリ/照明
```

ボーン操作を下パネルから外せると、モーフ欄を 2 カラム相当に広げやすくなる。

## 操作分類

### 現在値を登録する操作

対象:

- 選択ボーン
- 全ての親
- センター
- 表示中ボーン
- モーフ
- カメラ
- 照明
- アクセサリ
- 物理 ON/OFF

配置:

- ボーン / 物理: タイムライン下
- モーフ: 下パネルのモーフ欄にも登録導線を残してよい
- カメラ / 照明 / アクセサリ: 下パネル側に登録導線を残してよい

ボーンだけはタイムライン上の選択・キー表示との結びつきが特に強いため、タイムライン下へ寄せる。

### 既存キーを操作する操作

対象:

- 選択キー削除
- コピー
- ペースト
- 反転ペースト
- 範囲選択
- 補間コピー / ペースト

配置:

- タイムライン下を主導線にする
- 補間だけは下パネルの補間欄と連携する

### 物理 ON/OFF キー

`babylon-mmd` は VMD 由来の `physicsToggles` を読み、runtime の `rigidBodyStates` へ反映している。

MMD_modoki では、まず次を確認したい。

- 物理 ON/OFF キー入り VMD を読み込める
- `physicsToggles` が track に入る
- 再生中に `rigidBodyStates` が切り替わる
- project 保存 / 読み込み後も保持される

登録 UI は、ボーン操作 dock 内に置くのが自然。

```text
物理: (ON) (OFF) [登録]
```

この `登録` は通常のボーン回転キーとは別に、選択ボーンの `physicsToggles` を現在フレームへ upsert する操作として扱う。

## 段階実装案

### Phase 1: 表示だけ移す

- タイムライン下に `key-operation-dock` を作る
- 下パネルのボーン操作ボタン群と同じボタンを置く
- 既存 handler を呼ぶだけにする
- 下パネル側のボーン操作はまだ残す

目的は、操作場所を試すこと。

### Phase 2: 下パネルからボーン操作を外す

- `bone-section` から操作ボタン群を削る
- ボーン数値表示は必要最小限にする
- モーフ欄の横幅を増やす
- camera mode で壊れないよう、camera transform とは分離する

この段階で UI の主導線を切り替える。

### Phase 3: 物理 ON/OFF キー登録を追加

- 選択ボーンに紐づく `physicsToggles` を現在フレームへ登録する
- 既存キーがある場合は上書きする
- 近傍キーから通常のボーン値を壊さない
- project 保存 / 読み込みの確認をする

まずは UI と project 内保存まで。
VMD 書き出しは別タスク。

### Phase 4: 一括登録と選択補助

- 表示中ボーン登録
- 選択ボーン群登録
- 未登録選択
- 全て選択
- 範囲選択

複数ボーン編集の実用性はここで上がる。

ただし、`BOX選択`、`全て選択`、`縦選択` などをキー操作 dock のボタンとして常設すると、狭いタイムライン下を圧迫しやすい。
将来的には、これらをボタンで並べるより、タイムライン自体を表計算ソフト風に選択できるようにする案を優先して検討する。

### Phase 5: Auto Key との接続

Auto Key は単なる toggle として、タイムライン下またはビューポート下バーに置く。

最初は対象を絞る。

- ボーン操作のみ
- カメラは対象外
- モーフは対象外

モーフはスライダー操作でキーが増えやすいため、明示登録を維持する。

## Auto Key 案

Auto Key は、キー登録 UI 再配置後に入れたい補助機能として扱う。

MMD 本家の操作感では明示的な `登録` が中心だが、MMD_modoki ではギズモ操作や数値入力と連動した Auto Key があると、ポーズ編集の試行錯誤がかなり楽になる。
ただし、意図しないキーを大量に増やす危険があるため、最初は狭く始める。

### 最小仕様

初期実装では、Auto Key はボーン操作だけに限定する。

```text
Auto Key: ON / OFF
対象: 選択ボーン
発火: ギズモ操作、ボーン数値入力、回転/移動操作の確定時
登録先: 現在フレーム
登録内容: 現在のボーン位置 / 回転
除外: 再生中、シーク中、VMD 読み込み直後、モーフ、カメラ、照明、アクセサリ
```

最初は「操作中に毎フレーム登録」ではなく、「操作確定時に 1 回登録」を基本にする。
ドラッグ中に連続登録するとキーが増えすぎるため、必要になってから別モードとして検討する。

### UI 配置

Auto Key toggle は、タイムライン下のキー操作 dock に置く。

```text
[登録] [削除] [コピー] [ペースト] [反転P]   [Auto]
```

`Auto` は目立ちすぎないが、ON 状態は明確に分かる見た目にする。
誤操作防止のため、ON のときはタイムラインやステータス表示にも小さく状態を出してよい。

ビューポート下バーへ置く案もあるが、主導線はタイムライン下に寄せる。

### 実装方針

Auto Key 専用の登録ロジックを増やさず、既存の「現在フレームへボーンキー登録」処理を呼ぶ。

```text
ボーン操作確定
  -> Auto Key が ON か確認
  -> 再生中 / シーク中でないか確認
  -> 既存のボーンキー登録 action を呼ぶ
```

この形にすると、手動登録と Auto Key で保存形式や undo/redo の差が出にくい。

### Undo / Redo

Auto Key で登録したキーも、通常のキー登録と同じ command として扱う。

ただし、ドラッグ操作中に複数回発火する場合は、将来的に merge key を使って 1 操作にまとめる必要がある。
初期実装では操作確定時 1 回登録に制限し、undo 単位を単純に保つ。

### 将来拡張

後続で検討する対象:

- カメラ Auto Key
- モーフ Auto Key
- 選択ボーン群 Auto Key
- 物理 ON/OFF Auto Key
- 操作中連続 Auto Key
- Auto Key 対象の設定画面

カメラとモーフはキーが増えやすいため、ボーン Auto Key が安定してから別途判断する。

## 実装上の注意

### 既存 handler の再利用

最初から登録ロジックを増やさず、既存の登録 handler を呼ぶ。

UI の移動と登録処理の刷新を同時にやると、バグの原因を切り分けにくい。

### DOM と controller の責務

`BottomPanel` が `bone-section` と `morph-section` をまとめて持っているため、ボーン操作だけ抜くには責務分離が必要になる。

候補:

- `TimelineKeyOperationDock`
- `BoneKeyOperationController`
- `PhysicsToggleKeyController`

ただし Phase 1 では class を増やしすぎず、既存 UIController から呼ぶだけでもよい。

### Camera との分離

現行では camera transform が `bone-section` に同居している。

ボーン操作を下パネルから外す際、camera mode の数値編集が巻き込まれないようにする。

方針:

- model bone 操作 dock と camera transform 欄を分ける
- camera transform は下パネルに残す
- camera key 登録は camera 欄側に残す

### モーフ登録

モーフ欄は下パネルに残すため、モーフの `登録` は下パネル側にも置いてよい。

タイムライン下の登録ボタンを「選択タイムライン対象の登録」として汎用化すると混乱しやすい。
まずはボーン専用の登録導線として割り切る。

## Timeline Grid Selection 案

キー選択は、専用ボタンを増やすより、タイムライン表そのものを操作対象にする方が MMD_modoki らしく整理できる可能性がある。

表計算ソフトのように、行ヘッダ、列ヘッダ、左上角を使って選択する。

想定操作:

- 行ヘッダクリック: そのボーン / モーフ / カメラ track の全キーを選択
- フレーム番号ヘッダクリック: そのフレーム列にある全キーを選択
- 左上角クリック: 表示中または全体のキーを全選択
- タイムライン上ドラッグ: 矩形範囲選択
- Shift + クリック / ドラッグ: 範囲追加
- Ctrl + クリック: 個別追加 / 解除
- Delete: 選択キー削除
- コピー / ペースト: 選択範囲単位で実行

この方式にすると、キー操作 dock に `BOX選択`、`全て選択`、`縦選択`、`範囲選択` を常設しなくてよい。
キー操作 dock は `登録 / 削除 / コピー / ペースト / 反転P / 物理ON-OFF` のような実行操作へ絞れる。

### UI イメージ

```text
             frame 0  1  2  3  4 ...
左上角       ┌───┬───┬───┬───┐
ボーンA      │ ◆ │   │ ◆ │   │  ← 行ヘッダクリックでボーンA全キー選択
ボーンB      │   │ ◆ │   │   │
ボーンC      │ ◆ │ ◆ │   │ ◆ │
              ↑
              フレーム番号ヘッダクリックで列選択
```

### 実装方針

`timeline.ts` は既に以下のような分離を持っているため、選択拡張と相性は悪くない。

- ラベル canvas
- track canvas
- overlay canvas
- scroll container
- 選択状態

ただし、矩形選択や行/列選択を入れる場合は、次を先に整理したい。

- 行 index / track id / frame number の hit test
- 選択キー集合のデータ構造
- 選択範囲の overlay 描画
- delete / copy / paste command との接続
- track category 別の選択制限
- 表示中のみ選択か、全体選択か

### 段階案

1. 行ヘッダクリックで track 全キー選択
2. フレーム番号ヘッダクリックで列キー選択
3. 左上角クリックで全選択
4. 矩形ドラッグ選択
5. Shift / Ctrl 追加選択
6. copy / paste / delete と接続

最初はボタンを増やすより、行ヘッダクリックと列ヘッダクリックだけでもよい。
これだけでも `縦選択` や `全て選択` の UI ボタンを減らせる。

## v0.2 での最小セット

v0.2 で狙う最小セット:

- タイムライン下にキー操作 dock を追加
- `登録 / 削除 / コピー / ペースト / 反転ペースト` を置く
- 下パネルのボーン操作を縮小または削除
- モーフ欄を広げる
- 物理 ON/OFF キーの読み込み確認
- 物理 ON/OFF キー登録 UI の設計まで

実装まで進めるなら、物理 ON/OFF キー登録は小さく始める。

```text
選択ボーン + 現在フレーム + ON/OFF
  -> physicsToggles だけ upsert
  -> project 保存 / 読み込み確認
```

## 未決事項

- キー操作 dock をタイムラインパネル内に入れるか、全体下段の共通バーにするか
- タイムライン幅が狭いとき、dock を 1 段にするか 2 段にするか
- ボーン transform 数値をどこへ置くか
- モーフ登録をタイムライン下にも出すか、下パネル専用にするか
- 物理 ON/OFF キーをタイムライン上でどう表示するか
- Auto Key toggle をどこへ置くか
- 下パネルの camera mode と model mode の最終幅配分

## 結論

キー登録 UI は、下パネル中心からタイムライン下中心へ寄せる方がよい。

理由:

- ボーンキー操作はタイムラインと距離が近い方が自然
- 下パネルのモーフ欄を広く取れる
- MMD 本家の操作感に近づけやすい
- 物理 ON/OFF キー登録もボーン操作 dock に収めやすい

下パネルは「現在値を細かく編集する場所」、タイムライン下は「その値や選択キーを登録・操作する場所」として分ける。
