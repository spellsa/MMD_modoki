# グラフエディタ / タイムライン クローズアップ表示 構想メモ

更新日: 2026-08-04
状態: 構想 / 未実装

## このメモの役割

キーフレームの値と補間曲線を、グラフとして表示・編集する機能の方針をまとめる。実装仕様書ではなく、方向を決めるための設計メモである。

関連: [モーション補間・自動補完・カメラ追従の構想メモ](./motion-interpolation-camera-follow-concept-2026-08-04.md)

## 結論

グラフエディタは独立したウィンドウやパネルとして作らない。**タイムライン欄全体をクローズアップする表示モード**として作る。

1. 別ウィンドウにしない。タイムライン領域が解像度を変える形にする。
2. クローズアップの単位は、選択したものが属する単位とする。
3. 全体表示へ戻るボタンを添える。
4. 最初は読み取り専用で止める。編集は既存の補間パネルで行う。

別ウィンドウ方式は、ドープシートとグラフエディタの間で文脈が切れる。同じ場所で解像度が変わる形なら、折りたたみと展開の関係で理解できる。

## クローズアップの単位

**選択したものが属する単位をクローズアップする。**

| 選択したもの | クローズアップの単位    | チャンネル数の目安       |
| ------ | ------------- | --------------- |
| ボーン    | そのボーン1本       | 移動XYZ + 回転      |
| モーフ    | そのモーフが属する分類   | 分類内のモーフ数        |
| カメラ    | カメラ全チャンネル（候補） | X/Y/Z/回転/距離/FoV |

単位が型ごとに違うのは、画面あたりの情報密度を揃えるためである。モーフ1本は1チャンネルしかなく、単独でクローズアップしても画面が埋まらない。ボーン1本とモーフ1分類が、おおよそ同じ密度になる。

カメラは6チャンネルでボーンとほぼ同じ密度になる。既に下パネルの対象セレクタでモデルとカメラを同じ並びで扱っているため、同じ枠に乗せられる見込みがある。照明・影も同様。ただし現時点では候補であり、ボーンとモーフを先に成立させる。

## モーフの表示

### 分類

PMXが申告している表情パネルの分類（眉 / 目 / 口 / その他）をそのまま使う。モーフ名から推測して分類しない。物理互換補正で「モデル名や剛体名で分岐しない」としたのと同じ方針である。

### 全件を縦スクロール

分類内のモーフは絞り込まず、全件を縦スクロールで表示する。

よく使うモーフほどPMX上で先頭に並んでいるため、**モデル作者が並べた順がそのまま使用頻度順になっている**。こちらで並べ替えたり、キーの有無で絞り込んだりする必要がない。本家MMDの表情操作パネルも同じ扱いである。

絞り込みUIを作ると、状態の保存が必要になり、「出てこない」という迷子も生む。全件表示のほうが説明が要らない。必要になってから足す。

### 描画

値を線ではなく**帯（塗り）**で表示する。参考は Face And Lips のモーフ表示。

線グラフでモーフを多数並べると読めなくなる。帯なら「いつ、どれが、どのくらい効いているか」が一目で分かる。特に あ/い/う/え/お は基本的にどれか1つが立っている状態が正しいため、帯が重なっていれば即座に異常が見える。

### 縦方向のカリング

全件表示のため、行数がモデルによっては100を超える。`timeline.ts` が既に行っている「可視範囲だけを描画・計算する」を、時間軸だけでなく縦方向にも適用する。

## 表示の2段階

同じクローズアップモードの中に、解像度の違う2つの見方が入る。

|    | 見るもの             | 用途                 |
| -- | ---------------- | ------------------ |
| 俯瞰 | 分類内の複数モーフを帯で並べる  | どれがいつ効いているか。かぶりの発見 |
| 詳細 | 1チャンネルを大きく、曲線として | カーブの形の確認・編集        |

俯瞰で異常を見つけ、その帯をクリックすると詳細へ落ちる、という導線が自然である。戻るボタンがそのまま俯瞰への復帰になる。

## 補間曲線の描き方

MMDの補間曲線は0〜1に正規化されたベジェを**区間ごと**に持つ。一般的なアニメーションツールは接線を**キー**に持つ。この構造の違いが、描き方の分岐になる。

- **実値スケールに展開して描く**: 区間ごとの曲線が繋がって1本の線に見える。一般的なグラフエディタに近い。
- **正規化のまま描く**: 本家の補間パネルをタイムラインに埋め込んだ形になる。

どちらも成立するが別物である。前者を選ぶ場合、値の変化と補間曲線の対応をどう見せるかが課題になる。

## 段階

止め所を明示するため、次の順で進める。各段階の終わりで一度止められる。

### 段階1: モーフ分類のクローズアップ（読み取り専用）

最初に作る対象を**モーフ**にする。理由は次のとおり。

- 1チャンネルしかない
- 値域が0〜1固定のため、**縦軸スケールの問題が発生しない**
- 回転ではないため、Euler角の折り返しやクォータニオンが出てこない
- 補間曲線の描画ロジックはボーンと共通

レイアウト、目盛り、帯の描画、プレイヘッド、縦スクロール、戻るボタンまでを、他の難しさゼロで通しで固められる。

### 段階2: ボーンのクローズアップ（読み取り専用）

チャンネルを増やす。移動と回転で値域が違うため、縦軸の扱いをここで決める。

### 段階3: キーの選択と移動

矩形選択、時間方向・値方向のドラッグ。既存のキーフレームCommand経路に乗せる。

### 段階4: 接線ハンドルの編集

区間ベースの補間をどう掴ませるかを決める。ここが最も難しい。段階3までで実用に足りるなら、無理に進めない。

## 未決定事項

- 縦軸のスケールを自動フィットにするか、手動指定にするか
- ボーンのクローズアップで、移動と回転を同じ領域に描くか分けるか
- クローズアップ中に別のボーンを選択したとき、追従するか（詳細ペインとして振る舞うか、一度戻らせるか）
- ビューポートでボーンをクリックしたときの挙動も上と同じにするか
- 補間曲線を実値スケールに展開するか、正規化のまま描くか
- クローズアップモードの状態をプロジェクトへ保存するか、一時的な表示状態として扱うか
- カメラ・照明・影を同じ枠に載せる範囲
