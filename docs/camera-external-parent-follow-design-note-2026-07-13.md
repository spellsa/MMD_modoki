# カメラ外部親 / フォローカメラ再設計メモ 2026-07-13

## 2026-07-15 追試結果: 永久封印

v0.2.1 前に、カメラ外部親へ「X移動のみ」モードを追加する再試行を行った。
結論として、この方向は没。今後も同じ発想で再実装しない。永久封印とする。

### 試した実装

- カメラ外部親 UI に `X移動のみ` チェックボックスを追加する。
- 保存形式には `followMode: "inherit" | "xOnly"` と、X-only 用の `lockedWorldY/Z` を追加する。
- キー登録とプロジェクト保存/読み込みにも `followMode` と `lockedWorldY/Z` を通す。
- 通常の外部親行列を作った後、`xOnly` のときだけ親行列の移動成分をフィルタする。
- 具体的には、外部親元の X 移動だけを現在値として使い、Y/Z 移動と親回転は破棄する設計にした。
- 距離と視野角は MMD カメラ側の値を引き継ぐつもりで、距離 0 への落ち込みを避けるガードも入れた。
- 原因確認用に、登録時の距離/FOV/回転、外部親行列の移動成分、X-only フィルタ後の移動成分、最終 viewport camera の position/target/radius をログ出力した。

### 実機結果

- 外部親登録時点のログでは、距離や FOV は壊れていないケースがあった。
- それでも表示上は、真下を見る、距離が近すぎる、期待した構図にならない、という問題が残った。
- 仕様上は「距離と視野角を保持し、外部親元の回転と Y/Z 移動は捨て、X 横移動だけを見る」つもりだったが、MMD カメラの target / rotation / distance と Babylon の ArcRotateCamera の position / target / radius の変換が絡み、実装が不安定になった。
- 通常の外部親はすでに成立しているため、そこへさらに部分追従を後付けすると、外部親登録、キー登録、再生時評価、マウス操作、保存/読み込みの全経路に補正が漏れる。

### 敗因

- 「外部親そのもの」と「外部親から一部成分だけ参照するフォローカメラ補助」を同じ実装面に混ぜた。
- MMD カメラは `target + rotation + distance` が本体だが、表示側は ArcRotateCamera の `position / target / radius` と同期しており、どちらを正とするかが曖昧になった。
- 注視点を外部親ボーンへ合わせる処理と、カメラ位置を距離で再計算する処理と、親行列の成分フィルタが同じメソッド群に混ざった。
- `lockedWorldY/Z` のような固定値をキーやプロジェクトへ持ち込むと、登録時、seek 時、モデル再読み込み時、親ボーン未解決時の責務が増える。
- UI を単純なチェックボックスにしても、内部状態は単純にならなかった。
- ログで値を追っても、見た目の破綻が「登録時」「親行列」「表示カメラ同期」のどこに属するか切り分けづらかった。

### 方針

- `X移動のみ`、`水平保持`、`translationOnly`、`xzOnly`、`horizontalOnly` などのカメラ外部親フォローモードは実装しない。
- 少なくとも現行アーキテクチャでは永久封印。
- カメラ外部親は、親の移動と回転へ追従する通常の MMD 的な外部親挙動だけを扱う。
- フォローカメラが必要になった場合は、外部親の派生オプションとしてではなく、別機能として新規設計する。
- その場合も v0.2.1 には入れない。動画編集ソフト的な「追従カメラ」機能として、MMD カメラ保存形式とは分離した設計メモから始める。

### 実装状態

- 今回のコード変更は没として前コミット状態へ戻した。
- このメモは、同じ確認を繰り返さないための墓標として残す。

## 背景

v0.2.1 前の作業で、カメラの外部親登録に「水平保持」やフォローカメラ的な移動制限を追加しようとした。

水平保持そのものは有用だった。キャラクターのセンターや頭などにカメラを追従させつつ、ボーン回転でカメラが傾いたりねじれたりしない用途に向いている。

一方で、後から「Y軸無視」「X移動のみ」「キー登録時の同期」などを場当たり的に積み重ねた結果、登録、キー化、再生適用、マウス操作の責務が混ざり、最初に動いていた水平保持まで壊れた。該当変更は前コミット状態へ戻した。

## 今回わかったこと

- 外部親登録とカメラキー登録は別の操作として扱う必要がある。
- 外部親の「登録」ボタンは、MMD 寄せで外部親対象を注視点の基準にする挙動が自然。
- カメラキー登録は、現在の見た目をできるだけ保ったまま、キー payload に外部親状態を含める必要がある。
- 水平保持は「親の回転を無視する」だけで、「親の移動 X/Y/Z」は全部効くべき。
- フォローカメラ用途の「X移動のみ」などは、水平保持とは別機能として設計した方がよい。
- UI チェックボックスの状態を runtime state と同期するタイミングを間違えると、キー登録時にチェックが外れたり、古い座標系でキーが保存されたりする。
- この補助設定はカメラ外部親専用にする。モデルの外部親には水平保持や X 移動のみのようなカメラ向け追従モードを足さない。

## 失敗した実装パターン

### 1. キー登録直前に外部親登録と同じ処理を呼ぶ

外部親登録は、注視点を親原点へ合わせる副作用を持つ。

これをカメラキー登録直前にも使うと、ユーザーが見ていたカメラ構図そのものが変わり、キー payload の座標と外部親状態がずれる。

### 2. UI チェック状態を runtime state の唯一の正とする

チェックボックス変更だけでは runtime state に反映されない。

かといって、refresh 時に runtime state だけでチェックを上書きすると、ユーザーがチェックしてキー登録しようとした瞬間にチェックが外れる。

### 3. 水平保持と移動制限を同じ補正処理に混ぜる

水平保持は回転制御、X移動のみは移動制御であり、座標変換の意味が違う。

同じ `ignoreRotation` / `followXOnly` の流れに後付けすると、OFF 時に古い `lockedWorldY/Z` が残る、水平保持だけなのにY追従しない、などの混乱が起きやすい。

## 目標仕様

### 外部親なし

- 従来通りカメラキーは world 相当のカメラ値を保存する。
- マウス操作、数値入力、キー登録は既存挙動を壊さない。

### 外部親あり

- カメラキーには、親モデル、親ボーン、外部親オプションを含める。
- 再生/シーク時は、キーの外部親状態を適用してからカメラ姿勢を評価する。
- 親モデル/ボーンが見つからない場合は、警告または fallback を明示し、勝手に別ボーンへ置き換えない。

### 水平保持

- 親ボーンの world translation は X/Y/Z すべて使う。
- 親ボーンの rotation / scale は使わず、translation-only parent matrix として扱う。
- 目的は「追従先の移動にはついていくが、上半身や頭の回転でカメラが傾かない」こと。

### X移動のみなどのフォローカメラ補助

- カメラ外部親専用の補助として扱う。
- モデル外部親には適用しない。
- 水平保持との併用チェックボックスにはしない。
- 入れる場合は、ラジオボタンまたは select で単一の追従モードを選ぶ。
- チェックボックスを複数置くと「水平保持 ON + X移動のみ ON」のような組み合わせ状態が増え、キー登録/seek/UI refresh の同期が壊れやすい。

例:

```ts
type CameraExternalParentFollowMode =
    | "inherit"          // 通常: 親の移動XYZ + 回転に追従
    | "translationOnly"  // 水平保持: 親の移動XYZのみ追従、回転は無視
    | "xOnly";           // X移動のみ: 親のX移動のみ追従、Y/Zと回転は無視
```

## 推奨データモデル

boolean を増やすより、カメラ外部親専用の単一モードで表す。

```ts
type CameraExternalParentState = {
    modelPath: string | null;
    boneName: string | null;
    followMode: CameraExternalParentFollowMode;
    translationLock?: {
        worldY: number | null;
        worldZ: number | null;
    };
};
```

当面の最小実装では、`followMode: "translationOnly"` までを先に復活させる。

X移動のみを先に試す場合でも、チェックボックス併用ではなく同じ `followMode` の選択肢として追加する。

```ts
type CameraExternalParentStateV1 = {
    modelPath: string | null;
    boneName: string | null;
    followMode: "inherit" | "translationOnly";
};
```

## 実装方針

### 1. 行列生成を pure helper に寄せる

外部親行列の生成を `MmdManager` の巨大メソッドへ直接混ぜず、まず小さい helper にする。

入力:

- model world matrix
- bone world matrix
- follow mode
- locked translation

出力:

- parent matrix

最低限のテスト:

- `inherit` は入力 matrix を保持する。
- `translationOnly` は translation X/Y/Z を保持し、回転を identity にする。
- `xOnly` は translation X のみ現在値を使い、Y/Z はロック値を使い、回転を identity にする。
- `translationOnly` でも Y/Z が消えない。

### UI は単一選択にする

カメラ外部親 UI には、チェックボックスを複数置かず、次のようなラジオボタンまたは select を置く。

- 通常
- 水平保持
- X移動のみ

この UI はカメラモードの外部親設定だけに出す。モデル側の外部親 UI には出さない。

### 2. 登録とキー登録を分ける

外部親の「登録」:

- UI 選択を runtime state に反映する。
- MMD 寄せで注視点を親基準へ合わせる。
- これは構図が変わる操作でよい。

カメラキー登録:

- 既に runtime state に入っている外部親状態を読む。
- UI の未反映チェックを読む必要があるなら、runtime state へ反映するだけにし、注視点合わせはしない。
- カメラ pose は、外部親 state と同じ座標系で取得する。

### 3. UI state と runtime state の同期点を限定する

チェックボックス変更時:

- dirty として保持するか、即 runtime state に反映するかを決める。
- キー登録ボタン押下時に突然 refresh で上書きしない。

登録ボタン押下時:

- UI state -> runtime state -> refresh。

フレーム seek / キー再生時:

- key state -> runtime state -> UI refresh。

### 4. マウス操作は外部親空間で編集する

外部親ありのとき、マウス操作は「画面上のカメラを動かす」が先にあり、保存値は外部親空間へ逆変換する。

この変換と外部親登録処理を混ぜない。

## 段階実装案

### Slice 1: 水平保持だけ再実装

- UI: カメラ外部親専用の追従モード select/radio を追加し、選択肢はまず `通常` / `水平保持` にする。
- 保存: camera external parent key に `followMode` を保存。
- 再生: `followMode: "translationOnly"` のとき parent matrix を translation-only にする。
- モデル外部親には追加しない。
- X移動のみはまだ入れない。

確認:

- 親ボーンを上半身にして水平保持 ON。
- 親が Y 移動したらカメラも Y 移動する。
- 親が回転してもカメラは傾かない。
- キー登録後、seek してチェック状態と見た目が再現される。

### Slice 2: 登録とキー登録の責務分離

- 外部親登録ボタンの副作用を明文化する。
- キー登録は外部親登録ボタンを内部的に呼ばない。
- UI state の未反映問題があるなら、専用の state commit 関数を作る。

### Slice 3: フォローカメラ補助を検討

水平保持が安定してから検討する。

候補:

- `followMode: "xOnly"`
- `followMode: "xzOnly"`
- `followMode: "horizontalOnly"`
- 遅延追従

ただし v0.2.1 前には入れず、実験フラグまたは別タスクにするのが安全。

X移動のみを先に入れる場合:

- `followMode: "xOnly"` として単一選択にする。
- `translationOnly` との併用状態は作らない。
- UI 文言は「X移動のみ」。
- 期待挙動は、親の X 移動だけ追従し、Y/Z と回転は登録時の基準に固定する。
- このモードもカメラ外部親専用に限定する。

## テスト方針

pure helper の単体テストを先に書く。

テストしたいこと:

- translation-only で X/Y/Z が保持される。
- translation-only で回転成分が消える。
- xOnly で X だけ現在値になり、Y/Z はロック値になる。
- external parent key payload に follow mode が保存される。
- OFF のときは従来 payload と互換になる。

UI 実機確認:

- 外部親なしで既存カメラキー登録が壊れていない。
- 外部親あり、水平保持 OFF で親回転も移動も追従する。
- 外部親あり、水平保持 ON で親移動 XYZ は追従し、親回転は追従しない。
- X移動のみを入れた場合、親の X 移動だけ追従し、Y/Z と回転は追従しない。
- モデル外部親にはカメラ用追従モード UI が出ない。
- キー登録後の seek / 再生で同じ見た目に戻る。
- マウススクロール、右ドラッグ、中ドラッグの操作感が外部親なしと大きく変わらない。
